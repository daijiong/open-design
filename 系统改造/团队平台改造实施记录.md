# 团队平台改造实施记录

记录时间：2026-05-14 14:48:52

## 一、改造目标

本次改造基于《团队平台改造设计方案》落地，目标是将当前单人本地使用形态改造成团队成员可共同使用的平台：

1. 增加用户注册和登录能力，团队成员可以注册自己的账号。
2. 每个账号只能看到和访问自己的设计，管理员账号可以看到所有人的设计。
3. 只有管理员账号可以配置网站，普通成员只能使用设计工作台能力，不能修改系统配置。

## 二、账号与会话

### 2.1 后端新增认证模块

新增文件：

- `apps/daemon/src/auth.ts`
- `packages/contracts/src/api/auth.ts`
- `apps/web/src/state/auth.ts`
- `apps/web/src/components/AuthPage.tsx`

新增接口：

- `POST /api/auth/register`：注册账号。
- `POST /api/auth/login`：登录账号。
- `POST /api/auth/logout`：退出登录。
- `GET /api/auth/me`：获取当前登录用户。
- `GET /api/admin/users`：管理员查看用户列表。
- `PATCH /api/admin/users/:id`：管理员调整用户角色或状态。

实现规则：

- 首个注册用户自动成为管理员。
- 后续注册用户默认是普通成员。
- 使用 HttpOnly Cookie 保存会话标识，服务端只保存 token hash。
- 密码使用 Node `scryptSync` 加盐哈希保存，不保存明文密码。
- 禁止将最后一个有效管理员降级或禁用。
- 用户被禁用后会清理该用户的会话。

## 三、数据库结构

修改文件：

- `apps/daemon/src/db.ts`

新增表：

- `users`：用户账号表。
- `sessions`：登录会话表。
- `user_preferences`：用户偏好预留表。

项目表变更：

- `projects` 新增 `owner_user_id` 字段，用于标记设计归属用户。
- 新增项目 owner 索引，提升按用户过滤设计列表的查询效率。
- 项目查询结果新增 owner 信息：`ownerUserId`、`ownerName`、`ownerEmail`。

数据迁移规则：

- 已存在但没有 owner 的旧项目，在首个管理员注册时会被归属到该管理员名下。
- 管理员仍可看到所有项目。
- 普通成员只返回 `owner_user_id = 当前用户 id` 的项目。

## 四、设计访问隔离

### 4.1 项目列表隔离

修改文件：

- `apps/daemon/src/project-routes.ts`
- `apps/daemon/src/server.ts`

实现内容：

- `GET /api/projects` 必须登录。
- 管理员调用时返回所有项目。
- 普通成员调用时只返回自己的项目。
- 新建项目时自动写入当前用户 id。
- 导入项目时自动写入当前用户 id。

### 4.2 项目详情与文件访问隔离

已加入项目访问校验的能力包括：

- 项目详情读取。
- 项目更新、重命名、删除。
- 项目文件列表、读取、写入、上传。
- 会话、消息、评论、附件等项目相关数据。
- 项目导出、PDF 导出、归档导出。
- 项目部署、部署预检、部署记录。
- 项目相关媒体生成任务。
- 项目相关聊天和运行记录。

访问规则：

- 管理员可以访问所有项目。
- 普通成员只能访问自己拥有的项目。
- 非 owner 成员访问其他人的项目会返回 403。

## 八、当前环境注意事项

当前本机 Node 版本是 `v22.16.0`，仓库声明目标是 Node `~24`。

因此 daemon 全量测试和新 namespace 启动时，遇到了 `better-sqlite3` 原生模块 ABI 不匹配问题：

- 已安装的 `better-sqlite3` 是按 Node 24 ABI 编译的。
- 当前 Node 22 运行时需要不同 ABI。

建议后续在 Node 24 环境下重新执行：

```powershell
pnpm install
pnpm --filter @open-design/daemon test
pnpm tools-dev run web --daemon-port 17456 --web-port 17573
```

如果仍使用当前 Node 22，需要先重建原生依赖：

```powershell
pnpm --filter @open-design/daemon rebuild better-sqlite3 --pending
```

## 九、使用方式

启动系统后：

1. 首次访问会进入登录/注册页面。
2. 第一个注册账号会自动成为管理员。
3. 管理员注册后会接管旧项目，并可看到所有设计。
4. 后续注册账号为普通成员，只能看到自己创建或导入的设计。
5. 普通成员不能进入或保存管理员配置项。

常用启动命令：

```powershell
pnpm tools-dev run web --daemon-port 17456 --web-port 17573
```

访问地址：

```text
http://127.0.0.1:17573/
```

## 十、后续建议

本次改造已覆盖注册登录、项目隔离和管理员配置权限三项核心需求。后续如果要继续增强团队管理能力，建议按优先级补充：

1. 管理员后台用户管理页面。
2. 邀请码或邮箱域名白名单，避免开放注册。
3. 项目转移所有者能力。
4. 团队空间或项目共享能力。
5. 更完整的端到端登录和权限隔离测试。
