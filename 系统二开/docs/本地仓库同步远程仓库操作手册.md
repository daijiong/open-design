# 本地仓库同步远程仓库操作手册

本文档说明如何让本地仓库、自己 GitHub 账号下的仓库、原始开源仓库保持一致。

当前项目远程仓库约定：

- `origin`：自己账号下的仓库，用于日常推送。
- `upstream`：原始开源仓库，用于拉取官方最新代码。

当前仓库配置：

```text
origin   https://github.com/daijiong/open-design.git
upstream https://github.com/nexu-io/open-design.git
```

## 1. 查看远程仓库配置

在仓库根目录执行：

```powershell
git remote -v
```

预期能看到：

```text
origin    https://github.com/daijiong/open-design.git (fetch)
origin    https://github.com/daijiong/open-design.git (push)
upstream  https://github.com/nexu-io/open-design.git (fetch)
upstream  DISABLED (push)
```

说明：

- `origin` 是自己的仓库，可以推送。
- `upstream` 是原始仓库，只用于拉取，不用于推送。
- `upstream` 的 push 地址设为 `DISABLED`，是为了避免误推到原始仓库。

## 2. 日常同步流程

目标：把原始仓库 `upstream/main` 的最新代码同步到本地 `main`，再推送到自己的 `origin/main`。

### 第一步：切换到 main 分支

```powershell
git switch main
```

作用：确保当前操作的是主分支。

### 第二步：拉取原始仓库最新引用

```powershell
git fetch upstream
```

作用：从原始仓库获取最新提交、分支和标签。

注意：这一步只更新本地的远程引用，不会直接修改当前工作区代码。

### 第三步：合并原始仓库 main 分支

```powershell
git merge upstream/main
```

作用：把原始仓库最新代码合并到本地 `main` 分支。

如果没有冲突，Git 会自动完成合并。

### 第四步：推送到自己的 GitHub 仓库

```powershell
git push origin main
```

作用：把同步后的本地 `main` 推送到自己账号下的远程仓库。

## 3. 推荐的完整命令

```powershell
git switch main
git fetch upstream
git merge upstream/main
git push origin main
```

数据流向如下：

```text
原始仓库 upstream/main
        ↓
本地仓库 main
        ↓
自己仓库 origin/main
```

## 4. 同步前检查本地是否有改动

同步前建议先执行：

```powershell
git status --short --branch
```

如果看到未提交改动，例如：

```text
 M some-file.ts
?? new-file.md
```

说明本地工作区不干净。

处理方式有两种：

### 方式一：提交本地改动

```powershell
git add .
git commit -m "描述本次改动"
```

提交后再执行同步流程。

### 方式二：临时保存本地改动

```powershell
git stash push -m "同步前临时保存"
```

同步完成后恢复：

```powershell
git stash pop
```

## 5. 遇到冲突时怎么处理

如果执行：

```powershell
git merge upstream/main
```

后出现冲突，Git 会提示哪些文件冲突。

查看冲突文件：

```powershell
git status
```

打开冲突文件，找到类似内容：

```text
<<<<<<< HEAD
本地内容
=======
远程内容
>>>>>>> upstream/main
```

手动保留正确内容，并删除这些冲突标记。

处理完后执行：

```powershell
git add 冲突文件路径
git commit
```

最后再推送：

```powershell
git push origin main
```

## 6. 只想查看原始仓库有没有更新

如果只想查看是否有新提交，不想立即合并：

```powershell
git fetch upstream
git log --oneline main..upstream/main
```

如果有输出，说明原始仓库有本地还没有的提交。

如果没有输出，说明本地 `main` 已经包含原始仓库 `main` 的最新提交。

## 7. 不推荐直接使用 reset

不建议随意执行：

```powershell
git reset --hard upstream/main
```

原因：它会强制把本地代码改成原始仓库状态，可能丢失本地提交或未保存改动。

只有在明确要完全丢弃本地差异时，才考虑使用强制重置。

## 8. 常用排查命令

查看当前分支和工作区状态：

```powershell
git status --short --branch
```

查看远程仓库：

```powershell
git remote -v
```

查看当前分支提交历史：

```powershell
git log --oneline --decorate -10
```

查看本地 main 比 upstream/main 多了哪些提交：

```powershell
git log --oneline upstream/main..main
```

查看 upstream/main 比本地 main 多了哪些提交：

```powershell
git log --oneline main..upstream/main
```
