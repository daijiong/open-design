# 本地仓库同步远程仓库操作手册

本文档说明当前仓库如何和远程仓库同步。

当前策略：**本地 `main` 暂时锁定在 Open Design `0.7.0` 维护线，不再直接同步 `upstream/main`。**

原因：

- `upstream/main` 已进入后续开发线，包含新的主页和 0.8 方向改动。
- 当前本地仓库要保持 `0.7.0` 代码基线，同时保留我们自己的本地提交。
- 等上游发布新的正式 release 后，再单独评估是否升级。

## 1. 远程仓库约定

```text
origin   https://github.com/daijiong/open-design.git
upstream https://github.com/nexu-io/open-design.git
```

- `origin`：自己账号下的仓库，用于推送自己的代码。
- `upstream`：原始开源仓库，只用于拉取官方代码。
- `upstream` 的 push 地址应保持为 `DISABLED`，避免误推。

查看远程仓库：

```powershell
git remote -v
```

预期：

```text
origin    https://github.com/daijiong/open-design.git (fetch)
origin    https://github.com/daijiong/open-design.git (push)
upstream  https://github.com/nexu-io/open-design.git (fetch)
upstream  DISABLED (push)
```

## 2. 当前分支关系

本地 `main` 应跟踪：

```text
upstream/release/v0.7.0
```

检查：

```powershell
git status --short --branch
git branch -vv
```

预期类似：

```text
## main...upstream/release/v0.7.0 [ahead N]
* main  <commit> [upstream/release/v0.7.0: ahead N] ...
```

说明：

- `ahead N` 是我们自己的本地提交数量。
- 这是正常状态，不代表需要合并 `upstream/main`。

如果发现 `main` 仍跟踪 `origin/main` 或 `upstream/main`，执行：

```powershell
git branch --set-upstream-to=upstream/release/v0.7.0 main
```

## 3. 严禁直接合并 upstream/main

当前阶段不要执行：

```powershell
git merge upstream/main
git pull upstream main
git reset --hard upstream/main
```

这些命令会把 0.8 方向的开发代码合进本地 `main`，包括新版主页和大量插件体系改动，容易产生大面积冲突。

## 4. 日常同步 0.7.0 维护线

目标：只同步 `upstream/release/v0.7.0`，并保留本地提交。

### 第一步：切到 main

```powershell
git switch main
```

### 第二步：确认工作区干净

```powershell
git status --short --branch
```

如果有未提交改动，先提交：

```powershell
git add .
git commit -m "描述本次改动"
```

或者临时保存：

```powershell
git stash push -m "同步前临时保存"
```

### 第三步：拉取 upstream 引用

```powershell
git fetch upstream --prune
```

这一步只更新远程引用，不会修改当前代码。

### 第四步：查看 0.7.0 维护线是否有更新

```powershell
git log --oneline main..upstream/release/v0.7.0
```

如果没有输出，说明本地已经包含 0.7.0 维护线的最新提交。

如果有输出，继续下一步。

### 第五步：合并 0.7.0 维护线

```powershell
git merge upstream/release/v0.7.0
```

注意：这里只能合并 `upstream/release/v0.7.0`，不要把分支名改成 `upstream/main`。

### 第六步：验证版本和主页代码

确认版本仍为 `0.7.0`：

```powershell
Select-String -Path .\package.json -Pattern '"version"'
```

确认没有新主页组件：

```powershell
Test-Path .\apps\web\src\components\HomeHero.tsx
rg -n "What do you want to design\?|home-hero__rail" apps\web\src
```

预期：

- `Test-Path` 输出 `False`
- `rg` 没有输出

## 5. 推送到自己的 origin

如果只是日常新增提交，使用：

```powershell
git push origin main
```

如果这是第一次把本地 `main` 从旧的 `upstream/main` 状态改成 `0.7.0 + 本地提交` 后推送到 `origin/main`，远程历史会被改写，需要使用：

```powershell
git push --force-with-lease origin main
```

只在确认要让自己的 GitHub 仓库也回到当前本地状态时使用 `--force-with-lease`。

## 6. 误执行 git merge upstream/main 怎么办

如果刚执行：

```powershell
git merge upstream/main
```

并出现大量冲突，但还没有 commit，立即执行：

```powershell
git merge --abort
```

然后检查：

```powershell
git status --short --branch
```

应恢复为类似：

```text
## main...upstream/release/v0.7.0 [ahead N]
```

如果误合并已经提交，不要继续操作，先查看最近提交：

```powershell
git log --oneline --decorate -10
```

再根据备份分支或 reflog 恢复。当前仓库保留了一个旧状态备份：

```text
backup/main-before-v0.7.0
```

## 7. 以后评估新 release

只在上游发布新的正式 release 后评估升级，不直接跟 `upstream/main`。

查看 release tag：

```powershell
git fetch upstream --tags
git tag --list "open-design-v*" | Sort-Object
```

查看 release 分支：

```powershell
git branch -r --list "upstream/release/*"
```

如果发现新版本，例如 `upstream/release/v0.8.0`，先创建评估分支：

```powershell
git switch -c review/v0.8.0 upstream/release/v0.8.0
```

在评估分支中验证功能和冲突，不要直接改本地 `main`。

## 8. 常用排查命令

查看当前分支和工作区：

```powershell
git status --short --branch
```

查看分支跟踪关系：

```powershell
git branch -vv
```

查看本地 `main` 比 0.7.0 维护线多的提交：

```powershell
git log --oneline upstream/release/v0.7.0..main
```

查看 0.7.0 维护线比本地 `main` 多的提交：

```powershell
git log --oneline main..upstream/release/v0.7.0
```

查看是否误带入新主页：

```powershell
Test-Path .\apps\web\src\components\HomeHero.tsx
rg -n "What do you want to design\?|home-hero__rail" apps\web\src
```
